## 1. What the frontend is

Two surfaces that must look like one product:

| Surface | Tech | Port | Role |
|---|---|---|---|
| **Site** `super-travel/` | Static HTML + one CSS + one JS file, pages generated by `build.py` | 5173 | Marketing: home, journeys listing, 6 journey pages |
| **Concierge** (repo root) | Streamlit (`app.py`, `chat.py`, `plan_form.py`) skinned by `theme.css`, markup by `render.py` | 8501 | The interactive part: chat and form planner |

The site's "Plan a trip" links go to the concierge; the concierge nav links back to the site. There is no shared build step between the two, so **the design tokens are duplicated** and must be kept identical by hand (§5).

Constraints: no JS framework, no bundler, no npm. Fonts from Google Fonts, photos from Unsplash by id. Keep it that way unless a decision in §11 changes it.

## 2. Layout and who edits what

```
super-travel/
  index.html        HAND-WRITTEN. Home page, and the SOURCE for the shared nav, footer, favicon and chat-url meta
  styles.css        HAND-WRITTEN. All site styles, token block at the top
  main.js           HAND-WRITTEN. Reveal-on-scroll + wires data-chat-link to <meta name="chat-url"> (and appends ?journey=<slug> when the link has data-chat-journey)
  journeys.json     CONTENT. Source of truth for every journey (see backend-skeleton §6.4)
  build.py          Generator + validator + cache-buster
  journeys/index.html, journeys/<slug>/index.html   GENERATED. Never edit by hand
  serve.py          Dev server with Cache-Control: no-cache
app.py              Concierge frame: page config, theme.css, nav, st.navigation (Chat, Form)
chat.py             Chat page UI and state
plan_form.py        Form page UI
render.py           Python HTML builders for Streamlit (nav, hero, notice, itinerary, banner)
theme.css           Streamlit skin; mirrors site tokens
.streamlit/config.toml   Streamlit theme colours (must match tokens)
```

## 4. Flows

1. **Site → concierge:** any element with `data-chat-link` gets its `href` from `<meta name="chat-url">` (set on every page; change it once in `index.html`, then run `build.py`). Links open the concierge root, except journey-page CTAs that also carry `data-chat-journey="<slug>"`: `main.js` appends `?journey=<slug>` and `chat.py` starts the chat with that trip (§4.6).
2. **Concierge → site:** `render.nav_html(SITE_URL)` builds Services / Journeys links from `SITE_URL` in `.env`.
3. **Chat turn:** `chat_input` or example button (`ss.pending`) → user message → `st.status` shows tool events live → reply rendered by `chat.show()` → itinerary via `render.itinerary_html` + download buttons. Errors render as a `.notice`, never a traceback.
4. **Form → chat:** `plan_form.trip_message()` builds a sentence → `ss.pending` → `st.switch_page("chat.py")`.
5. **Reset:** fixed top-right pill (`.st-key-reset`) clears messages, session and pending prompt.
6. **Journey page → concierge:** CTA "Plan a trip" carries the journey slug (`data-chat-journey`, generated by `build.py`). `chat.py` reads `?journey=<slug>`, builds the opening message with `content.journey_prompt`, and ignores unknown slugs. The CTA label is unchanged; a "Plan this journey" label is a copy decision.

## 5. Design system

**Tokens exist in three places and must match:** `styles.css` `:root`, `theme.css` `:root`, `.streamlit/config.toml`. Change all three together.

| Token | Value | Use |
|---|---|---|
| `--bg` | `#fdf8f3` | Page background |
| `--bg-2` | `#f5f0eb` | Alternate sections, footer |
| `--accent` | `#e4a4bd` | Rose: italic words, rules, hover fills, assistant avatar |
| `--ink` | `#262626` | Text, dark sections, user avatar |
| `--ink-70` / `--ink-30` / `--line` | 70% / 30% / 10% ink | Secondary text, borders, hairlines |
| `--ok` / `--over` (Streamlit only) | `#a9c1a3` / `#d98a86` | Budget banner within / over |
| `--ease` | `cubic-bezier(0.16,1,0.3,1)` | All entrances |
| `--nav-h` | 80px | Fixed nav height, scroll padding |
| `--pad-x` | `clamp(20px,4vw,64px)` | Page gutters |
| `--max-w` (site) | 1600px | Container width (Streamlit main column is 980px) |

**Type:** League Spartan only (300–900). Headings use `.display`: weight 900, uppercase, letter-spacing -0.05em, line-height 0.8; the last word goes in `<em>` (italic, lowercase, rose). Label/eyebrow: 10px, weight 900, letter-spacing 0.4em, uppercase, with a 32px rose rule before it. Do not introduce a second typeface.

**Shape and motion:** pill buttons (999px radius), hairline 1px dividers instead of boxes, generous vertical padding (`clamp` in the 96–192px range for sections), fade/slide-up reveal via `.reveal` + `--d` stagger delay, all disabled under `prefers-reduced-motion`.

**Breakpoints (site):** 1100px, 900px, 520px, plus `prefers-reduced-motion`. Mobile-first fixes go in those blocks at the end of `styles.css`.

**Voice:** warm, concise, "we"; no exclamation marks, no emoji.

## 6. Generated vs hand-written (the build contract)

| You want to change | Edit | Then |
|---|---|---|
| A journey's text, budget, days, image | `journeys.json` | `python super-travel/build.py` |
| Journey page or listing *layout* | `build.py` (the f-strings) | run `build.py` |
| Home page copy/sections, nav, footer, favicon, chat URL | `index.html` | run `build.py` (copies nav, footer, chat URL to generated pages) |
| Site styles or JS | `styles.css`, `main.js` | run `build.py` (asset hash `?v=` changes so browsers refetch) |
| Concierge look | `theme.css`, `render.py` | restart not needed; Streamlit reruns |

Guards: `test_site.py` fails if generated pages are stale, local links break, the hash is out of date, or the "View Journey" button stops being the card's only link. `build.py` rejects invalid journey data. Run `python -m unittest test_site` before finishing any site change.

For any visible change, look at it in a browser at desktop and phone width (375px), check the console for errors, and click through the flow it touches. Verify the chat with a real or mocked turn: example prompt → status line → table → banner → downloads → Reset.

## 9. Quality checklist (run on every UI change)

- [ ] Works at 375px, 768px and desktop; no horizontal scroll
- [ ] Keyboard: visible focus ring (`:focus-visible`), logical tab order, links vs buttons used correctly
- [ ] Images have `alt`, explicit `width`/`height`, `loading="lazy"` below the fold
- [ ] Text contrast ≥ 4.5:1 (rose `#e4a4bd` on cream is decorative only; never body text)
- [ ] `prefers-reduced-motion` respected; no content hidden if JS fails (`.js` class gate)
- [ ] Nav, footer, tokens identical on site and concierge
- [ ] No console errors; no broken local links (`test_site`)
- [ ] Empty, loading, error, and success states all designed (chat: empty hero, status, `.notice`, itinerary)
- [ ] No raw model/user text in HTML without `esc`
